## Windows-specific adaptation notes

- `tools/ocs/setup.ps1` (new) mirrors `setup.sh`: disk-space check, pinned
  download to `$env:LOCALAPPDATA\OpenCADStudio-v2026.46\`, digest
  verification before execution, version banner print. Uses `curl.exe` and a
  .NET SHA-256 (this machine's PowerShell 5.1 cannot autoload `Get-FileHash`).
- The portable exe is a **GUI-subsystem** binary: PowerShell's `&` call
  operator does not wait for it and leaves `$LASTEXITCODE` unset, so
  `setup.ps1` reads the real exit code via `Start-Process -Wait`. Python's
  `subprocess` waits on the process handle normally, so the test tooling is
  unaffected.
- Default exe paths are platform-specific (`resolve_exe()` in
  `ocs_smoke_test.py`): `%LOCALAPPDATA%\OpenCADStudio-v2026.46\OpenCADStudio.exe`
  on Windows, `~/.local/opt/OpenCADStudio-v2026.46/OpenCADStudio.AppImage` on
  Linux. Override order: `--exe` → `$OCS_EXE` → legacy `$OCS_APPIMAGE`
  (Cloud Shell compatibility) → platform default. `test_drawing_index.py`
  pins a per-platform asset digest table (win32/linux) and refuses a binary
  whose digest does not match the pinned asset for the running platform.
- `prepare_run_dir()` now refuses ANY drive root (`C:\`, `D:\`, …) as a
  `--workdir` base, not only the root of the current drive; POSIX behavior
  unchanged. `test_safe_workdir.py` creates directory symlinks with
  `target_is_directory=True` (required on Windows, ignored on POSIX) and
  reports the symlink sub-parts as skipped — not passed — when the session
  lacks symlink privilege (this laptop has it; both parts ran).
- The stale-refusal rebuild hint printed by `drawing_index.py` now shows the
  interpreter actually running (a quoted absolute `python.exe` path on
  Windows) so it stays copy-pasteable.

## Observed transient flake (honest record)

One embedded smoke-test run (inside the milestone-2 suite, before the
recorded runs above) failed at S12 with:

```
save refused: {'code': 'save_failed', 'error': 'replace \\?\C:\…\fixture_edit.dxf:
Unable to remove the file to be replaced. (os error 1175)', 'ok': False}
```

Windows error 1175 = "Unable to remove the file to be replaced": something
held the freshly written DXF open while OCS's save did its remove+rename —
transient antivirus/indexer interference, not an OCS or tooling defect. The
same step then passed in three consecutive standalone runs and in the
recorded suite run (4 of 4 after the single occurrence). Mitigation if seen
again: re-run the affected suite; no automatic retry was added anywhere
(mutation sends stay exactly-once by design). Real customer drawings saved
through the future assistant layer will need the same caution — a save that
fails on a file lock must surface, not silently retry.

  unchanged, and the digest table keeps both platforms.

  entity types beyond Line/Circle/Text, DWG/blocks/XREFs/layouts, GUI
  channels, field-level provenance via `raw`.
