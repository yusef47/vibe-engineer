## What was built

| File | Role |
|---|---|
| `tools/ocs/drawing_index.py` | Read/index layer: builds an index of an existing DXF through the real `--serve` channel (reuses milestone-1 `Serve`), answers deterministic queries with staleness gates. CLI: `index` / `query`. |

Design rules honored: reads only (no entity mutation in the index path);
`Serve.mutate()` inherited unchanged (one send, `StaleStateError` on stale —
no auto-replay); nothing deletes caller data (no `rmtree`); the source file is
hashed before/after indexing and a changed file refuses to produce an index;
every entity record carries `classification: null` (no structural claims until
an engineer confirms labels); anything OCS did not return is recorded as the
sentinel `unknown`, never invented.

## Staleness proof 1 — file changed through OCS ⇒ old index refuses (exit 3)

The demo file was changed **through OCS itself** (open → bounded
`entities_set` color:1 on the circle → `save` → close; written:1, file bytes
changed `59052920…` → `3a301dfa…`):

```
$ python3 tools/ocs/drawing_index.py query --index tools/ocs/out/demo_index.json --query count
STALE INDEX — refusing to answer from tools/ocs/out/demo_index.json
  reason: source file changed since indexing:
          path='/…/fixture_base.dxf'
          indexed_sha256=59052920c8a3985bdb96078c271af0b5b94d9e85ecd8df989c416961b4f4d7ce
          current_sha256=3a301dfa085e5c0eb57892c59e772a63205dc45154d3f588f9871d7fe864ec91
  rebuild only through an explicit new indexing operation:
    python3 tools/ocs/drawing_index.py index --file <drawing> --json <index>
(exit code 3; `count`, `types`, `layers`, `handle:`, `text:` all refuse)
```

An explicit re-index accepted the new file (new sha recorded, count answered 6
again, circle color now `{"Index": 1}` in the fresh index). The pristine
fixture used for the content proof was never touched (hash re-verified, R5).

## Staleness proof 2 — unsaved in-session edit ⇒ live revision check refuses

A fresh copy was opened in a live session; `index_document` recorded revision
0; `entities_set` color:3 (accepted, revision 0→1, NOT saved). The file hash
was still the indexed one, so only the live revision check could catch this:

```
$ idx.count(srv=srv, document_id=doc)   # live context
IndexStaleError: live document revision 1 != indexed revision 0: the session
changed the drawing after this index was built …
$ idx.count()                            # file-hash-only context
6   (correct: the file on disk is unchanged)
$ idx2 = di.index_document(srv, doc)     # explicit rebuild records revision 1
$ idx2.count(srv=srv, document_id=doc)
6
```

R5 additionally proved the two signals are independent: after the OCS
edit+save, all four query forms refused with both hashes named; after the
rebuild, `entity(handle)` reported the new color.

## Unsupported / notable pinned-build behavior recorded

| Behavior | Evidence (real binary, v2026.46) |
|---|---|
| `file_identity` advertised by `capabilities` but unimplemented | plain passive send → `{"ok":false,"error":"unknown op: file_identity"}`; recorded in the index as `unsupported_by_pinned_build` with the verbatim reply (R7) |
| Sending an op as a protocol-1 **mutation envelope** can mutate state even when the op is unimplemented | `file_identity` with a valid envelope+request_id moved revision 0→1 and set `dirty=true` (refused a subsequent plain `close` with `document_dirty`); a bogus op name in an envelope answered `unknown_operation` with no side effect. The read layer therefore probes only with plain passive sends; documents stay untouched (rev 0, dirty False through indexing — asserted by R7) |
| `close` of a dirty document is refused | `{"code":"document_dirty","error":"Save the document or pass discard:true"}`; indexing never makes the document dirty (reads only), so its own close is accepted |
| `query` without `type` returns ALL entities; unknown type filter → `ok:true, count:0` | used for enumeration; no type guessing needed |
| Revision advances on mutations, NOT on save | entities_set 0→1; save kept revision |
| Reopening an already-open path keeps the same document id | the pre-open `state` check keeps caller-owned documents open (never closed by the index layer) |
| Unknown type filter replies ok/count:0 | index never invents entity types; `type` is stored verbatim |

## Known limits (honest gaps)

- Pagination: `next_offset` was always `null` at fixture scale; the loop
  following it is defensive and its offset path is unverified against the
  real build (a >page-size drawing would exercise it).
- Only entity types present in the synthetic fixture (Line, Circle, Text)
  were exercised; Arc/Polyline/Insert/MText/Dim etc. are unverified — the
  index stores whatever types OCS returns, verbatim.
- Text search is a local substring match over recorded values; no fuzzy/
  semantic matching (deliberate — no AI in this milestone).
- `classification` is null everywhere by design; engineer-confirmed labels
  are a later, separate mechanism.
- Provenance is per entity (file+hash+revision+handle). Field-level provenance
  inside an entity is covered by the verbatim `raw` payload rather than
  per-field entries (documented trade-off to keep the index small).
- DWG, blocks with attributes, XREFs, layouts, locked/frozen layers: not
  exercised (same scope as milestone 1; fixture contains none of these).
- GUI (`--mcp`), assistant panel, viewport capture: out of scope here, still
  on the workstation list (headless `--serve` only).

## Review round 2 (Codex on `fc733ac`) — fixes and evidence

Codex raised two trust-contract gaps; both fixed on this branch before merge.

**Gap 1 — unchecked public accessors.** `entities()`, `summary()` and the CLI
`handles` form exposed drawing facts without passing the freshness gate.

Fix: `entities()`/`summary()` now take the optional live context and gate;
the CLI `handles` form routes through the gated `entities()` (file-hash
check; exit 3 on refusal). New U8 is a reflective regression guard: the set
of public accessors is compared against an explicit gated list (exempt:
`check_fresh`, `to_json`, `to_json_dict`, `from_json`, and the raw `data`
container, which exposes the stored snapshot itself, never an
interpretation), then a patched `check_fresh` proves all 7 fact accessors
raise instead of answering.

New R9 (real binary): CLI index of a copy → `query --query handles` prints
all 6 handles (exit 0) → the copy is changed THROUGH OCS (bounded edit +
save) → the same `handles` query exits 3 with `STALE INDEX` naming both
hashes; and all 7 python accessors (`entities`, `summary`, `count`,
`count_by_type`, `count_by_layer`, `search_text`, `entity`) raise
`IndexStaleError` on the changed file.

**Gap 2 — fail-open indexes that disk cannot validate.** An index built from
a dirty/unsaved OCS document (or with no readable source file/hash)
contained live-session facts that only a hash of the file on disk guarded —
insufficient. 

Fix: `DrawingIndex.check_fresh` now treats `document_dirty=true` or
`source_sha256=null` as live-REQUIRED. Every query on such an index must
pass a live session context whose **session id**, **document identity**
(registered path) and **document revision** all match the indexed ones;
otherwise it refuses with the new `IndexUnverifiableError` (a subclass of
`IndexStaleError`, so the CLI exits 3 with an `UNVERIFIABLE INDEX` banner
and the reason). Session identity is verified on ALL live checks — even for
file-anchored indexes — because document ids and revision counters are
per-session. The optional live context for clean file-backed indexes keeps
its no-false-staleness behavior when the document is simply closed (file
hash already verified). New U9/U10 pin the dirty/no-hash rules against
canned replies (no-context / other-session / closed-document /
diverged-revision all refuse; matching session answers); U11 pins the
session-identity check for clean indexes; R10/R11 repeat both rules on the
real binary:

- R10 (real): open a copy → unsaved `entities_set` → `index_document`
  records `document_dirty=true`, revision 1, file hash unchanged →
  `count(srv, doc)` answers 6 (live-verified) → `count()` refuses
  ("unsaved in-session document… no live session context") → document
  closed with `discard:true` (dropping the test's own unsaved edit; file
  re-verified unchanged) → `count(srv, doc)` refuses ("no longer open").
- R11 (real): `new` + `index_document` on the empty in-memory document
  (`document_dirty=false`, `source_sha256=null` — isolating the no-hash
  rule) → live-verified `count` answers 0 → `count()` refuses
  ("no readable source file/hash") → after `close`, `count(srv, doc)`
  refuses ("no longer open").
